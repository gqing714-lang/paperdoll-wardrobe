# 纸娃娃换装扩展 · v0.2.30

可通过 SillyTavern 的第三方扩展地址安装，也可从仓库更新。

## v0.2.30 · 剧情配色

- `<新衣服>` 的 HEX 颜色现在直接使用 Overlay（覆盖）公式叠加到原素材。暗部、亮部和褶皱来自原图；接近黑色的色值每个通道最低按 48/255 处理，以免阴影全部压成黑色，所以 `#000000` 看起来是有细节的深灰黑。
- 未声明染色区的部件使用“整体”。多染色区由图包 `dyeRegions` 的 `name`、`frontMask`、`backMask` 明确声明；模型只接收真实名称，脚本拒绝未知或有歧义的名称。未指定的区域保持原图。指定“整体”和局部时先染整体再染局部。
- 剧情款从原素材建立新配方，不叠加基底现有的手动染色。手动高级染色继续使用原来的参数与算法；旧衣柜中的 `multiply`／`target` 配方保持原样，不自动重算。手动调整剧情款的某个染色范围时，该范围切换回手动染色算法。
- 前片、后片、衣柜缩略图和 GIF 导出共用同一渲染路径。素材最好为中性黑白灰，彩色底图也会参与 Overlay 混合，结果受原底色影响。

## 本版重点

- 状态栏的完整 HTML 与全部外观样式现在都由 `[纸娃娃] ❃ user状态栏` 正则的“替换为”内容负责；扩展 CSS 中没有状态栏规则。
- 脚本只把最新实时纸娃娃挂进正则留下的 `data-stpd-inline-doll` 槽位，不再还原消息类名、加工摘要或添加任何状态栏装饰。
- 状态栏只依赖不会被 SillyTavern 添加 `custom-` 前缀的 `data-*` 标记，因此不再需要类名兼容补丁。
- 每个槽位最多挂载一个实时渲染节点；整人轮廓滤镜与容器阴影均明确关闭，用户素材中的脚底椭圆落影原样保留。

- 移除状态栏真实小人上的 CSS 轮廓阴影；像素画边缘只显示素材原像素，不再生成偏移剪影。
- 用户原素材中的脚底椭圆落影完整保留；它不会被当作整个人形轮廓剪影处理。

- 移除回复末尾状态栏中位于小人槽位下方的半透明人形底纹；纸娃娃本身、缩放、位置、图层顺序和状态栏布局保持不变。
- 状态栏采用已确认的新版横向布局：真实小人约 `90×160`，摘要与小人同高；“全部状态”打开后，十一栏在下方独占整行，不再拉长左侧空位。
- 去掉旧版大框与“当前／历史”角标，改为轻量边线、渐隐纹理和两层 `❃` 动效。窄于 350px 时小人约为 `82×146`。
- 正则的十一栏识别规则不变，只更新替换 HTML 骨架；内置正则结构版本升级为 4，固定 ID、自动同步与用户禁用状态保留逻辑不变。

- SillyTavern 会为消息 HTML 的类名增加 `custom-` 安全前缀；本版状态栏已经取消类名依赖，正则样式与纸娃娃槽位统一使用 `data-*` 标记。
- 挂载逻辑只处理带 `data-stpd-status-version='5'` 的配套状态栏，不会改动正文或其他美化；不新增轮询、DOM 观察器或第二套渲染器。
- 已有同 ID 规则会自动更新，仍保留用户手动设置的禁用状态。

- 修复 0.2.21 安装后正则栏没有出现 `[纸娃娃] ❃ user状态栏` 的问题。`bootstrap.js` 会先独立同步配套正则，再以新版地址加载纸娃娃主体；主体前置初始化即使失败，也不会再截断正则安装或继续命中旧脚本缓存。
- 配套规则集中到单一的 `status-regex.js`，主脚本与启动器复用同一个定义，没有复制第二份规则或增加生命周期分支。
- 替换字段由命名捕获组改为数字捕获组，兼容用户固定使用的 SillyTavern 1.15；正则仍支持 Windows／Linux 换行、中英文冒号和完整十一栏。
- 覆盖更新时使用 `style-v0.2.27.css`，确保 manifest、脚本、样式和安装包版本一致。

- 修复 0.2.20 中状态栏裸着纵向铺开、状态栏内部没有小人的问题。右下角原有悬浮特写与状态栏小人是两个不同容器；本版会把全身纸娃娃真正挂到横向卡左侧。
- 配套正则的结构改为版本 2，并为小人槽位提供类名与 `data-*` 双重定位；扩展在消息渲染完成和点击展开时都会幂等检查一次。
- 状态栏关键布局不依赖 `color-mix()`，继续兼容 Android WebView。
- 最新完整十一栏状态卡会显示扩展当前实际造型。若模型返回了无法应用的衣物名，扩展先恢复保存方案，再显示真实纸娃娃，而不是留下空槽位。
- 仍然只有最新卡片挂载动态小人；没有新增轮询、DOM 观察器或第二套眨眼计时器。

- 扩展每次正常加载时都会按固定 ID 把内置的 `[纸娃娃] ❃ user状态栏` 同步到 SillyTavern 全局正则列表；不再需要下载或手动导入独立正则文件。
- 正则内容集中在独立的 `status-regex.js` 中；同步只使用 `extension_settings.regex` 与 `saveSettingsDebounced()`，不依赖 manifest 生命周期钩子、正则引擎动态导入或外置 JSON。
- 已有规则会更新并移到列表末尾，同时保留用户手动设置的“禁用”状态；重复加载不会生成副本。
- 模型回复末尾的 `<user状态>` 会在显示阶段变成两层折叠状态栏：先显示安静的 `❃`，展开后是“真实纸娃娃＋摘要”，再点“全部状态”查看完整十一栏。
- 只有当前最新状态卡挂载动态纸娃娃。它直接复用换装面板的穿戴、图层、染色、表情与唯一眨眼计时器；历史卡不拿当前穿搭冒充旧快照，也不创建后台动画。
- 状态格式统一为头饰、颈饰、内衣、内裤、衣装、外搭、手饰、袜子、鞋子、其他配饰、表情。旧栏目不会再进入模型提示词。
- 消息完成、重新渲染、编辑、切换候选、切换聊天和页面重载都会重新定位最新状态卡；挂载幂等，不使用轮询或 MutationObserver。

- 剧情生成新款时，没有分区的部件默认使用“整体”；有分区的部件默认只使用图包声明的真实分区，不再自动给配方追加整体染色。
- 手动高级染色中的“整体”仍然保留。旧衣柜、旧配方以及模型明确写出的整体染色继续兼容；用户主动同时设置整体与分区时，仍按原来的先整体、后分区顺序叠加。
- v0.2.18 曾只调整自动配色范围与提示词；v0.2.30 新增剧情款专用的 Overlay 像素处理。

- v0.2.17 使用原有高级染色引擎自动校准成品色；该路径已由 v0.2.30 的 Overlay 替代。已有 `target`／`multiply` 衣柜配方仍可显示，手动调色和旧方案不会被自动重算。
- 深灰素材生成浅色款时可能需要超过 200 的明度，因此明度滑杆上限扩展至 400；已有参数值和原有渲染步骤不变。

- 简化 `<新衣服>`：标签内每件直接写“区域｜基底｜新名称｜染色配方”，不再要求重复的 `生成：` 前缀。
- 解析器继续兼容 v0.2.13／v0.2.14 的 `生成：区域｜……` 写法，已有提示词和旧回复不会失效。
- 四栏、真实基底、染色区和色值校验保持不变；省略前缀不会降低误解析防护。

- 修正新衣服协议中的误导性占位格式：默认配方现在明确为 `整体=#RRGGBB`，模型不得再原样输出“范围”。
- 未声明局部染色区的基底只能输出一个整体色；声明了局部染色区时，必须逐字使用动态清单中的真实名称。
- 新款名称不得暗示原基底不存在的材质、版型、长度、图案或结构，减少“毛呢外套”被命名成“长风衣”一类视觉不一致。

- 新增“剧情新增配色款”。剧情确认 user 获得、穿上或完成改色的新款时，模型可输出 `<新衣服>`；扩展会以现有部件为基底创建染色配方并保存到当前衣柜。
- 新衣服协议独立附加在状态提示词之后，不覆盖已有自定义提示词；可在扩展设置中单独关闭，也可在提示词工作台查看完整正式注入内容。
- 支持整体染色和图包声明的真实局部染色区。区域、基底、名称、色值与数量均由脚本校验，无效行不会改变当前穿搭。
- 新款先入柜再解析 `<user状态>`，因此可在同一轮立即穿上；仅获得但未穿时只新增衣柜条目。
- 同素材、同栏目、同语义区域且完整配方相同的款式自动复用；同名不同配方自动编号，不复制 PNG。

- 新增“导出透明特写 GIF”。在换装、衣柜或表情页搭好当前造型后，点击预览下方按钮即可下载。
- 导出只保留右侧 `160×222` 特写，不包含左侧全身小人、预览背景或界面控件。
- GIF 会保留当前穿搭、前后片、发型层级、整体／分区染色和表情，并按三帧眼皮完成一次眨眼后停约 5 秒循环。
- 导出器只在点击按钮时加载和计算，平时不会增加纸娃娃的常驻负担。

- 新增独立“衣柜”页。素材页负责试穿和调色；原色或染色后的当前部件都可保存为一个衣柜条目。
- 同名部件自动编号：第一次保存为原名，再次保存为“原名01／原名02”；保存后可随时改名、复制或移除。
- 每个衣柜条目保存独立的整体高级调色和全部分区染色配方；不会复制 PNG，也不会让同一素材的多个配色互相覆盖。
- 支持多个衣柜。可新建、切换、重命名和删除；当前衣柜就是本轮提供给 AI 的可用部件池。
- 衣柜按头饰、颈饰、内衣、内裤、衣装、外搭、手饰、袜子、鞋子、其他配饰十个穿戴区域分类，并在区域内继续按真实素材栏目分层展示。
- 通用配饰可在头饰、颈饰、手饰和其他配饰之间自行归类；普通服装自动继承正确分类。
- 穿搭方案归属于保存时的衣柜；旧方案与 user 绑定继续兼容。
- 旧“服装池”首次加载时自动迁移到默认衣柜；共享配饰 1／2／3 只迁移一次。
- 默认 AI 状态使用十个穿戴区域加表情的十一栏完整结构；只发送用户起的衣物名称，不发送色号和染色参数。历史回复仍可兼容读取，但旧栏目不会继续注入。

- 每次正式生成前都会强制刷新并重新登记纸娃娃状态提示词，不再只依赖上一次缓存。
- 扩展设置和提示词工作台会显示“已登记／未注入／注入失败”、当前预设、字符数、最近成功时间与具体原因。
- “编辑内容预览”只代表尚未保存的草稿；“当前正式注入内容”与实际构建逻辑完全一致，可手动重新注入检查。
- 配饰 1／2／3 中的同一个共享素材只算一个部件，不再因为“呆毛”等素材误报模型识别名重复。
- 真正重名时仍会向模型提供当前状态，但会拒绝有歧义的自动换装结果，避免穿错部件。
- 后发饰现在固定渲染在鬓发后面，现有素材和图包无需重新制作。

- 新增 ZIP 素材图包导入。扩展会先检查图包名称、版本、部件、前后片、染色区和图片尺寸，再允许导入。
- 图包支持更新与副本导入，不需要因为增加一件衣服而重新安装整个扩展。
- 上衣、下装、连衣裙、外套支持可选后片；后片附属于当前逻辑部件，不会继承上一件衣服的后片。
- 图包后发支持“后发（前）＋后发（底）”：两张属于同一逻辑部件，并固定显示在人模前后。
- 左右辫严格使用一张主图；“放到身前／放到身后”只切换这张图的渲染层级，主图蒙版也随层级一起生效。
- 旧版图包如果带有辫子置后图片或置后蒙版，仍可导入；新版会明确提示并忽略这些旧字段。
- 上衣和下装的前后片会同步交换遮挡顺序；外套固定在连衣裙和普通上下装之上。
- 原高级染色模块新增“整体／染色区”作用范围选择；每个区域都能独立调整颜色、染色强度、饱和、明度、对比和保留暗线。
- 图包部件可带多个分区染色蒙版，同一区域的完整高级参数会同时作用于该部件自己的前片和后片。
- 图包图片使用独立图片存储，避免大量 PNG 直接写进设置文本导致空间不足。
- 在更衣室换装页点击“导入图包”，或在扩展设置点击“导入素材图包”，即可选择 ZIP。
- 图包制作格式见 `图包制作说明.md`；不会写 JSON 的使用者可以只提供图片，由图包制作者代为整理。

- 换装与表情页改为实时工作台：电脑端预览在左、部件在右；手机端上方保持紧凑双预览，下方素材区独立滚动。
- 普通换装支持“自动／3列／4列／5列”密度并保存选择；自动模式在手机端默认三列，电脑端按可用宽度排布。
- 普通部件卡删除重复状态行，缩略图改用素材原始比例；保存后的款式集中在分类衣柜中管理。
- 大型导入卡改为当前图层旁的小型导入按钮，调色和特殊层级放到素材列表后方，减少手机首屏拥挤。
- 新增“脱服装／清配饰／全部清空”快捷操作，只改变当前穿着，不删除素材、服装池或已保存方案。
- 保留全身与特写同时展示；任何控件都不会覆盖纸娃娃画面。
- 延续低对比的浅暖色纸偶工坊风格，素材预览使用柔和暖白底。
- 按 PSD 备注替换六张嘴巴与眨眼三帧。
- 新增眼白、上挑瞳孔、脸红、黑脸、紫脸、眼泪和汗滴。
- 新增五部件组合的可命名状态表情。
- 衣柜中的每件衣物都可自定义名称；当前衣柜中的名称会成为模型可使用的部件池。
- 生成时按九个区域提供当前衣着、当前衣柜与可用状态，并明确实时状态优先于设定中的默认衣着。
- 状态块中的部件只能从同一区域的当前衣柜选择，表情只能从可用状态选择。
- 脚本读取回复末尾的 `<user状态>` 并即时换装，不再修改或重新保存回复正文。
- AI 换装结果只在当前运行期间即时生效，不写入方案或本地存储。
- 下一次回复没有有效状态块时，自动恢复当前 user 绑定的已保存方案。
- 新增特写左侧／右侧位置选项，选择结果会自动保存。
- 更衣室使用双预览、实时状态台以及换装／衣柜／表情／方案／设置五页布局。
- 扩展界面新增状态提示词入口，支持中文动态变量、格式校验、实际提示预览和多个自定义预设。
- 系统默认提示词保持只读；修改后可另存为自定义预设，并随时切换或恢复默认。
- 保留 user 方案绑定、三帧眨眼、染色和导入功能。

## 覆盖安装

```bash
ST_DIR="$(find "$HOME" -maxdepth 4 -type d -name SillyTavern 2>/dev/null | head -n 1)"
cd "$ST_DIR/public/scripts/extensions/third-party"
rm -rf st-paperdoll-wardrobe-local-test
unzip -o "$HOME/storage/downloads/st-paperdoll-wardrobe-local-test-v0.2.27.zip"
```

然后重启 SillyTavern。

## 状态格式

```text
<user状态>
头饰：蝴蝶结
颈饰：领结
内衣：白色内衣
内裤：白色内裤
衣装：白衬衫、短裤
外搭：毛呢外套
手饰：无
袜子：过膝袜
鞋子：乐福鞋
其他配饰：无
表情：害羞
</user状态>
```

十一栏必须全部存在；没有穿戴时写“无”。扩展保存的配套规则只在 Markdown 显示阶段美化状态块，不修改聊天原始正文，也不会把生成后的状态栏 HTML送回模型。规则使用固定 ID 幂等更新，所以重复加载不会产生副本；用户在正则面板中手动禁用该规则后，扩展更新它时也会保留这一选择。

状态栏中的小人不是静态预览图。配套正则生成完整状态卡、交互结构、全部样式和小人挂载点；扩展只把现有 `renderStage` 渲染结果挂到最新卡片中，因此与更衣面板、悬浮特写共用同一穿戴状态、图层顺序、染色、分区染色、表情和眨眼运行时。

## 新衣服格式

```text
<新衣服>
外搭｜大外套｜暮樱大衣｜外衫=#B86F82;里层=#F1DDD8
衣装｜短裙｜酒红短裙｜整体=#8B0000
</新衣服>
```

- 每件直接从区域名开始；旧版行首的 `生成：` 仍可识别，但不再需要。
- 区域和基底必须来自本轮注入的可用分类部件。
- 没有局部染色区的基底默认使用“整体”；有局部染色区的基底默认只使用动态清单花括号内的真实范围，不自动追加整体。
- “整体”仍是有效且兼容的高级染色范围。正文明确改变整件底色时模型可以使用它，用户也始终可以在手动面板中选择它；主动同时设置整体与局部时仍会叠加。
- RGB 色值用于 Overlay 覆盖层，模型不需要根据灰度素材自行提亮；脚本按原图像素应用颜色，不会推算阴影、高光或高级染色参数。
- 素材可以来自扩展内置资源、相册或已导入的外部 ZIP 图包；网络图片如禁止浏览器读取像素，则无法生成染色预览。
- 每轮最多三件。相同配方复用已有条目；名称冲突时自动编号。
- 标签只代表新增到当前衣柜。是否穿上仍由随后完整的 `<user状态>` 决定。

## 提示词预设

在 SillyTavern 扩展设置中找到“纸娃娃换装”，选择“编辑提示词”。编辑器支持以下中文变量：

```text
{{当前状态}}
{{可用分类部件}}
{{可用染色区}}
{{当前衣着}}
{{当前表情}}
{{可用部件}}
{{可用表情}}
```

新版预设建议使用 `{{当前状态}}`、`{{可用分类部件}}` 和 `{{可用表情}}`。`{{可用染色区}}` 由独立的新衣服协议自动使用，无需手动加入自定义预设。旧版四变量预设继续有效；变量会在每轮生成前替换为实时数据，格式不完整时不会覆盖当前有效预设。

## 衣柜使用

1. 在“换装”页选择一个服装或配饰，可保持原色，也可先进行整体／分区高级调色。
2. 点击“保存到衣柜”；若当前已经来自衣柜，可选择“覆盖当前款”或“另存新款”。
3. 在“衣柜”页改名、复制、移除或切换分类。移除衣柜条目不会删除素材图包。
4. 多个衣柜之间切换时，当前穿着不会被强制脱下；只有当前衣柜和当前仍穿着的名称会提供给 AI。
5. 到“方案”页保存一整套穿搭；方案会归入当前衣柜，并可继续绑定到当前 user。
